# AURA Product Vision

AURA is a private, local-first, user-owned AI Operating Identity.

It is not a chatbot, dashboard, or set of use-case buttons. The long-term product is a trusted identity layer between a human and the increasingly autonomous software around them.

## The Four Layers

## Helper

AURA Helper does useful computer work: clone repositories, draft replies, create coding jobs, open apps and URLs, prepare workflows, summarize context, and operate files inside safe workspace boundaries.

## Guardian

AURA Guardian is the human intent firewall. Today it protects AURA-managed actions: shell commands, file writes, paste/send, memory storage, workflow replay, import/export, model cost/privacy, and identity boundaries. Ambient OS-wide protection is planned but not claimed.

## Memory

AURA Memory is persistent user-owned continuity, not chat history. It stores preferences, workflows, safety decisions, identity context, site/app patterns, project notes, and repeated corrections. It is local-first, inspectable, editable, deletable, exportable, importable, scoped, and encrypted at rest.

## Identity

AURA Identity records who AURA is acting as: Personal, Work, Company, or Session. Actions, memory usage, approvals, and boundaries are logged under the active identity. The local identity has an Ed25519 fingerprint; external agent-to-agent verification is a future network layer.

## Demo Promise

Within five minutes, AURA should show:

- a living desktop presence;
- useful Helper action;
- visible Guardian protection;
- memory that changes a later response;
- active identity and ledger;
- honest limitations.

## North Star

The user should feel:

> This is my AI. It remembers me, protects me, helps me, and represents me.
